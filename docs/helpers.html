Shell Helpers

Optional shell scripts that integrate your shell environment with naTE's wide-column and CWD-tracking features.

naTE ships a small collection of shell scripts in the helpers/ directory. None of them are required — naTE works without them — but each one unlocks a specific feature that needs cooperation from the shell.

Where to find them depends on how you installed naTE:

Source checkouthelpers/ in the repository root
Portable tarballhelpers/ inside the extracted directory
.deb / .rpm package/usr/share/nate/helpers/
AppImageusr/share/nate/helpers/ inside the mounted image

In the examples below, replace /path/to/naTE/helpers with the location for your install — for example /usr/share/nate/helpers on a packaged install.

OSC7-bash.sh — CWD Tracking (Bash)

naTE can track the current working directory of any running SSH or PTY session in real time. This allows it to restore sessions to the correct directory and (in future) display the CWD in the tab title. The mechanism relies on the shell emitting an OSC 7 escape sequence every time the directory changes.

OSC 7 has the form:

ESC ] 7 ; file://hostname/current/path ST

Modern shells like fish and zsh (with the right prompts) emit this automatically. For Bash, source this script in your ~/.bashrc:

source /path/to/naTE/helpers/OSC7-bash.sh

The script detects whether it is running under Bash and sets up PROMPT_COMMAND to emit the sequence after every prompt:

if [ -n "$BASH_VERSION" ]; then
    PROMPT_COMMAND='printf "\033]7;file://%s%s\033\\" "$(hostname)" "${PWD}"'
    PS1='\u@\h:\w\$ '
else
    PS1='\u@\h:\w\$ $(printf "\033]7;file://%s%s\033\\" "$(hostname)" "${PWD}")'
fi

Remote sessions: Source this in your remote ~/.bashrc (on the SSH server) so that naTE on your local machine can track the CWD as you navigate on the remote host.

What CWD tracking enables

  • Session restore accuracy: When naTE restores a session after a restart, it cds to the last directory you were in rather than the home directory.
  • Reconnect to correct directory: If an SSH session drops and you reconnect, naTE lands you in the same directory you were working in.

OSC7.sh — CWD Tracking (POSIX / simple)

A simpler alternative to OSC7-bash.sh for shells where you just want to patch PS1 directly. It embeds the OSC 7 sequence in the prompt string using Bash's \[...\] non-printing markers:

PS1='\u@\h:\w\$ \[$(printf "\033]7;file://%s%s\007" "$(hostname)" "${PWD}")\]'

Source it the same way:

source /path/to/naTE/helpers/OSC7.sh

Which one to use? Prefer OSC7-bash.sh on Bash — it uses PROMPT_COMMAND, which is more reliable and doesn't interfere with an existing PS1 customization. Use OSC7.sh if you want to paste a single line into an existing prompt setup.

ls.sh — Width-aware ls

The problem

naTE lets you set a column width (what the shell thinks the terminal is) independently of the tile's visible width. For example, you might run with 1024 columns so that long log lines are captured in full, while the tile on screen is only 80 columns wide.

The trouble is that ls reads the PTY column width (1024) and formats multi-column output to that width — so each ls listing is one very wide row of filenames that extends off-screen.

The fix

naTE writes the tile's actual visible column count to a temp file and exposes the path in the environment variable $NATE_VPCOLUMNS_FILE. The ls.sh wrapper reads that file and passes -w <cols> to ls, so output wraps at the visible width instead of the PTY width.

unalias ls 2>/dev/null

ls() {
    cols=""

    if [ -n "$NATE_VPCOLUMNS_FILE" ] && [ -r "$NATE_VPCOLUMNS_FILE" ]; then
        cols=$(cat "$NATE_VPCOLUMNS_FILE")
    fi

    if [ -n "$cols" ]; then
        command ls --color=auto -w "$cols" "$@"
    else
        command ls --color=auto "$@"
    fi
}

Source it in your ~/.bashrc (or ~/.zshrc):

source /path/to/naTE/helpers/ls.sh

Behaviour

  • When run inside naTE with a wide column width, ls wraps at the tile's visible width.
  • When run outside naTE (no $NATE_VPCOLUMNS_FILE), the wrapper falls back to plain ls --color=auto with no -w override — no change in behavior.
  • Any arguments you pass to ls are forwarded unchanged (-la, -lh, paths, etc.).

Tip: If you use a wide column width globally (e.g. PtyLineWidth = 1024 in config.ini), sourcing ls.sh on both your local and remote machines makes directory listings readable at a glance in any tile size.

top.sh — Alternate-screen top

The problem

The standard top on some systems exits cleanly — it restores the terminal when you press q. However, busybox top (common on Alpine Linux and embedded systems) does not use the alternate screen buffer. When it exits, its output is left mixed into your regular scrollback, making the terminal look garbled.

The fix

The top.sh wrapper manually switches to the alternate screen buffer before invoking top and restores the main buffer on exit — including when interrupted with Ctrl+C.

top() {
    cleanup() {
        printf '\033[?1049l'   # switch back to main screen
    }

    trap cleanup INT TERM

    printf '\033[?1049h'       # switch to alternate screen

    command top "$@"
    rc=$?

    cleanup
    trap - INT TERM

    return "$rc"
}

Source it in your ~/.bashrc on any remote host that runs busybox top:

source /path/to/naTE/helpers/top.sh

Behaviour

  • top runs on the alternate screen buffer.
  • When top exits normally (q) or is killed with Ctrl+C / SIGTERM, the main screen is restored.
  • The exit code of top is preserved.
  • All arguments are forwarded to the real top unchanged.

Standard top: The GNU/procps top already handles the alternate screen correctly. This wrapper is a no-op overhead on those systems but does no harm — it still works correctly.

Installing the Helpers

From the AppImage

The helpers are bundled inside the AppImage. Extract them with:

./naTE-x86_64.AppImage --appimage-extract
# helpers are in squashfs-root/usr/share/nate/helpers/  (path may vary)

Alternatively, copy them directly from the helpers/ directory on GitHub.

From source

They are in helpers/ at the root of the repository.

Recommended ~/.bashrc snippet

Source whichever helpers apply to your workflow. A complete setup for a developer using naTE with wide columns and busybox remotes:

# ~/.bashrc (local machine)
source ~/helpers/OSC7-bash.sh   # CWD tracking
source ~/helpers/ls.sh          # width-aware ls
# ~/.bashrc (remote servers running busybox)
source ~/helpers/OSC7-bash.sh   # CWD tracking for session restore
source ~/helpers/ls.sh          # width-aware ls
source ~/helpers/top.sh         # alternate-screen top

Copying helpers to a remote host: A quick way to get them there is SFTP — use Terminal → Send Files from an active SSH session to upload the scripts to ~/helpers/ on the remote machine.
